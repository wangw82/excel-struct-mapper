# Support

## Getting Help

Use GitHub Issues for reproducible defects and focused feature requests. Before opening an issue:

- Review the [documentation index](docs/README.md) and [FAQ](docs/faq.md).
- Search existing issues for the same behavior.
- Reduce the report to a minimal example with synthetic data.
- Include the Go version, library version, operating system, and relevant error chain.

Community support is provided on a best-effort basis. The project does not guarantee response times, implementation dates, or individual integration support.

## Supported Versions

Before the first tagged release, only the current default branch is evaluated. After releases begin, the support table in [SECURITY.md](SECURITY.md) defines versions eligible for security fixes. General bug fixes normally target the latest release line.

## Scope

Support covers the public mapper and XLSX adapter APIs. Debugging application-specific models, repairing corrupted workbooks, operating private infrastructure, and evaluating macros or formulas are outside project support.

Never attach credentials, personal data, customer records, internal addresses, confidential identifiers, or proprietary workbooks. Replace them with the smallest synthetic input that reproduces the behavior.

## Security Reports

Do not use public issues for suspected vulnerabilities. Follow [SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting.
